# Architecture and implementation boundaries

## Components

`hooks/register.js` is the single official mods entry point. All functions receiving `$` are top-level declarations in that file, as the documented static analyzer requires. The hook dependency graph imports only local, pure ES modules; no Node, DOM, dynamic import or external packages enter the hooks sandbox. It registers one immediate command and one pane renderer. It observes lifecycle events and leaves their payloads unchanged. It neither contributes skills nor registers tools.

`lib/usage.js` normalizes transcript counters, identities and calendar operations. `lib/quota.js` resolves explicit IANA local reset times to instants, handles DST ambiguity/gaps, and constructs half-open weekly intervals. `lib/pricing.js` prices de-duplicated requests with a dated, explicit model/speed API catalog and propagates uncertainty/coverage. `lib/view-model.js` builds interval totals and bounded 45-day or 20-quota graph pages. `lib/visuals.js` builds escaped SVG strings. Presentation is data-only: no SVG script, foreignObject, remote resources or DOM injection. Standard controls handle keyboard input and selections. There is no Client renderer and no ui.message handler.

`scanner/index.mjs` runs as a dependency-free Node child via the documented `$.process.run(argv, {stdin, timeoutMs})`. Arguments remain separate; no shell interpolates paths or data. It streams JSONL because the host's text-file read API is not suitable for transcripts beyond its 4 MiB read bound. Node 20+ is an explicit external runtime dependency, not an assumed Node API inside a hook.

`preview/index.html` is generated by `scripts/build-preview.mjs`. It packages the same hook/visual functions with a browser-only host simulation and explicitly fictitious fixtures. It is never imported by the installed mod.

## Refresh and rendering

Opening schedules work on `$.clock.after`; it does not wait for import inside a render. A 30-second timer refreshes while open. Turn/measurement events schedule a coalesced refresh. The UI is built from the last snapshot; changing range, grouping, selected day/quota, metric, theme, model or speed requires no filesystem work. Configuration changes invalidate the snapshot with a revision check, preventing an in-flight old scan from publishing stale configuration data.

A hook scan and CSV export do not overlap. Across sessions, an atomic lock directory serializes the persistent writer. Readers encountering a live owner receive the last compatible snapshot with a busy flag. Compatibility includes timezone, subagent inclusion, source scope, reset day/time and price edition; a mismatched or legacy snapshot is not shown as weekly totals. A crashed owner's lock is reclaimed when its process no longer exists. The host cancels timers on mod unload. /clear and /resume are not treated as final shutdown, since session.start does not fire again for them.

The process has a 120-second upper timeout. The indexer uses an approximately 18-second parsing budget per pass and checkpoints newline boundaries. Directory enumeration/cache loading/aggregation are outside that parsing interruption mechanism; extremely large or slow/network trees can still exceed the process timeout. Use local disk roots and inspect explicit errors rather than assuming import completed.

## Counting algorithm

1. Discover local JSONL sources, canonicalize explicitly configured roots, skip internal links and the plugin cache.
2. Reuse per-file records for unchanged size/mtime once TTL and response-speed enrichment (`detailVersion: 3`) is complete; check a prefix fingerprint when a file changes. This is an optimization, not protection against deliberate file tampering.
3. Read appended UTF-8 bytes from a committed newline boundary. An incomplete final line is retried after growth; a valid final object without newline is counted but not byte-committed.
4. Accept assistant responses with usage, a valid timestamp, a nonsynthetic model and an identity. Use API message ID, then request ID, then UUID. Hash identity globally, not per session. Keep no conversation text.
5. Merge repeat blocks/copies by maximum cumulative field values. A main response copied into an agent transcript remains main. Agent-only identities obey the include-subagents filter.
6. Price each unique response at its own recorded response speed, prompt-length tier and TTL split, then aggregate each unique response into a local-calendar day and exact model ID, and independently into `[quotaStart, quotaEnd)` by its timestamp. Within each quota, keep day/model sub-buckets so calendar filters can clip a cycle without prorating totals. Any future timestamp is excluded until a later scan, retained in the record cache, and reported.
7. Persist per-file numeric records, the registry and daily/weekly snapshot with temporary-file-plus-rename writes under the lock.

The top-level cache creation count includes its TTL sub-buckets. Missing creation total may be synthesized from those buckets, but never added to them. Read/write/new input/output have separate columns. The cache-hit ratio uses weighted token sums, not daily ratio averages.

Full record retention enables deduplication and preserves counters when source logs are pruned. Rewriting a file does not decrement previously observed usage: this is retained observational history, not a mutable-file checksum report. Old records from a removed configured root are excluded. Changing local account identity is not an automatic source partition.

## Weekly quota contract and upgrade

The record-cache schema and directory remain `v1`, so previously indexed timestamps can be regrouped without rereading unchanged transcripts or losing pruned source records. The derived snapshot adds `weeks`, `quota: {timeZone, resetDay, resetTime, signature}` and `asOf`. Each week has exact UTC `startMs`/`endMs` plus local calendar label and day/model sub-buckets. The global daily and weekly aggregates are generated from the same de-duplicated response set, never by splitting a pre-aggregated calendar-day total proportionally.

`This quota` uses the current half-open reset interval. `7d`/`30d` retain calendar-day semantics and clip overlapping cycles at the filter's local midnight; weekly sums equal daily sums for identical filters. `All time` starts at the first observed quota and fills zero-use cycles between it and the current quota, without inventing an extra earlier cycle from the first day's midnight. Pagination does not alter period totals or export scope. One response spanning a reset is assigned to its earliest observed transcript timestamp, not apportioned to an unverifiable server accounting time.

Weekly boundaries are resolved independently in the configured IANA zone. Calendar stepping uses seven local dates, not a fixed millisecond duration. Ambiguous wall times choose the earlier occurrence; nonexistent wall times shift forward by the gap. Cached local-time resolutions make per-response grouping inexpensive. Tests cover Lisbon, UTC, New York, Kathmandu and Lord Howe, including 30-minute DST transitions. A new reset setting reinterprets all retained history; historical changes to the account's actual reset schedule are not inferred or versioned.

The UI exposes `reset-day` and `reset-time`, persisted with the existing `preferences-v1` key; old saved preferences remain valid. Invalid edits keep the last valid setting. An invalid stored initial configuration is reset with an explicit notice. No account setting or limit is written. The live limits panel remains an unmodified independent source, with no conversion from local tokens into a quota percentage.

## Limits and trade-offs

Read/write per model per day cannot be recovered from an aggregate that lacks those dimensions. No artificial allocation of account totals or stats-cache totals is attempted. The current account-limit API is deliberately a separate section; no OAuth scraping, private endpoint or Admin API key is used.

Rows larger than 32 MiB are skipped with a diagnostic, using bounded line buffers. Invalid/unrecognized rows may be skipped. UUID fallback cannot promise perfect cross-copy attribution. Numeric counters use safe integers; ordinary token volumes fit comfortably, but this is not an arbitrary-precision ledger. Rendering is bounded by daily/weekly and model pages. Initial indexing and merging still scale with the number of locally retained responses.

Source logs are trusted as data supplied by the local user, not cryptographically authenticated billing records. Nested links are not followed, but this implementation does not attempt to defeat hostile concurrent filesystem replacement attacks. Cache files and directories request user-only POSIX permissions; Windows inherits directory ACLs. Paths and model names are local metadata and remain visible in diagnostics/cache.

## Official API surface

Calls: `$.settings.read`, `$.command.register`, `$.ui.open`, `$.ui.close`, `$.ui.resolve`, `$.ui.invalidate`, `$.store.get`, `$.store.set`, `$.clock.now`, `$.clock.after`, `$.clock.every`, `$.process.run`, `$.env.get('ProgramFiles')`, `$.session.usage`, and the `$.plugin.root` property.

Hooks: `command.describe {command:account-stats}`, `config.set {key:language}`, `classic.ConfigChange`, `session.start`, `command.run {command:account-stats}`, `ui.render {component:Pane}`, `turn.complete`, `session.measure`, `ui.close`, `classic.SessionStart`, `session.end`.

The scanner reads HOME/USERPROFILE-equivalent home information, CLAUDE_CONFIG_DIR and optional APPDATA using Node's inherited process environment. It never reads credential values or files. The authoritative compatibility check is the user's actual `claude plugin validate --strict` and Desktop runtime, not the public typings snapshot or the simulated host tests.

## Selected-cycle card · 1.1.1 presentation fix

`cycleSvg(week, view, theme)` renders all four counters from the **selected, model-filtered week**, not the entire range. The total uses the existing `total(week)` helper (read + write + input + output). All categories remain visible even when the chart metric is narrowed to cache; zeros are shown explicitly. A two-column category grid sits to the right of the total. Partial-quota notices have a reserved footer row. Accessible/terminal text includes input, output and the total formula. This change does not modify scanning, quota boundaries, persistence or token arithmetic.

## 1.2.0: native spacing and API-equivalent cost

Every top-level section is a non-shrinking native `Box` with one `marginTop` layout row (except the first). Thus the quota card, selected-cost card, model controls/card, official limits and footer have actual host spacing. The browser adapter now interprets those props instead of manufacturing SVG/select margins through CSS. Native host metrics can differ from the browser simulation.

`priceRecord` runs only after deduplication; its cost object is added with `addPriced` separately from integer token totals. `costOf` never guesses a request tier from an aggregate. Missing TTL is represented by lower/upper write costs. Unverified pricing retains unpriced token counts. `chartValue(..., 'cost')` uses the upper endpoint for axis bounds, with stacked known/minimum category costs and a translucent unknown-TTL segment. Other graph metrics do not hide input/output or cost cards.

The existing v1 record schema is extended, not replaced. Old extant logs get a one-time, resumable TTL-enrichment read. Retained counters from deleted/pruned sources survive; their unknown metadata is explicit. Money is derived when aggregating, so a tariff update needs no transcript reread. Snapshots record their price edition. CSV appends nine-decimal USD cost columns and coverage/status metadata. See `PRICING.md` for assumptions, sources, unsupported pricing variants and catalog maintenance.


## 1.3.0: presentation-only language integration

`lib/i18n.js` is a pure, cached formatter/catalogue factory. It resolves the Code `language` value as a supported language-name alias or BCP 47 code, keeps regional tags for Intl formatting, and selects one of seven complete message catalogues under `lib/locales/`. English is the explicit unset/unsupported fallback. Portuguese without a region selects Portugal. Catalogues have exactly the same keys and interpolation parameters. Per-render contexts avoid a mutable locale global in shared visual modules. No translation service is used.

`hooks/register.js` reads only `language` from the official merged `$.settings.read()` result. It never serializes, stores, logs or sends the complete settings object, which may contain unrelated secrets. Detection lives in the module's session state, not `preferences-v1`. Startup/open/refresh reads and post-`next` configuration observation refresh the language; rejected proposals do not become effective values. A short deferred re-read handles host update ordering. `command.describe` also updates the command description. Settings failures keep the last successfully detected locale, with an explicit settings notice.

Known errors/notices are message keys and arguments rather than permanently translated strings, so an already visible validation error changes language on the next draw. Raw scanner/OS detail remains unchanged in Diagnostics. ISO keys, input HH:mm, model IDs, timestamps, reset zone, pricing edition and accounting are not localized. `quotaExportLabel` preserves v1.2.0 export spelling; `quotaLocalLabel` and `quotaIntervalLabel` are presentation-only Intl formatters. CSV headers/numeric cells remain machine-stable.

The public Code `language` setting controls response/dictation language. No separate Desktop UI-locale field is documented in the consulted mod API; the implementation does not invent one or scrape Desktop preferences. It does not infer language from user conversations. Unsupported-language and default reasons are shown in the panel's settings.

SVG labels get conservative host-independent font sizing, additional monetary-axis room and explicit column widths. The 1.2.0 native `Box` margins remain. `preview/app.js` simulates `$.settings.read` and configuration events; its language dropdown is demo-only and never loaded by the installed mod. Regional formatter tests use the actual Intl implementation, and Playwright measures SVG bounds/collisions in both themes. Host font metrics and native control appearance can still differ from the browser simulation.


## 1.4.0: recorded response speed

`lib/speed.js` accepts only the response usage values `fast` and `standard`; missing or conflicting evidence is `unknown`. It deliberately ignores request intent and session toggles. `mergeSpeed` enriches missing metadata and retains a sticky conflict flag so duplicate ordering cannot turn contradictory known evidence into a confirmed mode. See [the full evidence and upgrade contract](FAST_MODE.md).

`priceRecord` uses an explicit verified Fast tariff table. Unsupported model/speed combinations are unpriced. Unknown speed retains a standard-equivalent comparison with `assumedStandardTokens`/`assumedStandardRequests` counters and visible warnings, never as a confirmed Standard request. `addPriced` carries disjoint `speeds` buckets through daily, weekly, per-model and selected-period totals. The persisted `speed` preference filters those derived buckets without rescanning or changing weekly boundaries.

The raw numeric record cache keeps the same version and path and adds just the speed enum plus optional conflict flag. `detailVersion: 3` performs one enrichment pass over available logs. Deleted source records retain their counters but cannot invent missing speed. No new host API calls, model requests, telemetry or credentials are introduced. `lib/speed-i18n.js` contributes the same keys and parameters to all seven supported translation catalogues.
